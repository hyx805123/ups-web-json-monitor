# CMDB 功能扩展清单（待选）

> 状态核对：**2026-11-09 · 对应 v1.5.1**。本文档写于 v1.2 时期，已按当前代码逐项复核，
> 标注了已完成与部分实现的项。共 **41 项待做**（A7 · B6 · C6 · D7 · E6 · F4 · G5），
> 另有 H 类工程遗留 6 项。

对照成熟 CMDB / 动环监控系统（ServiceNow CMDB、Zabbix、华为 iMaster NCE、
SolarWinds、SNMP Manager 等），列出本系统尚未具备、但对 UPS 资产管理有实际价值的功能。

**当前系统已覆盖**：设备台账、分组、模板、告警规则与推送、实时看板、
历史永久留存与折线图（含三相机型分相电压电流）、冷数据 gzip 归档与容量回收、
断线自动重连、SNMP→Web JSON 直采、双主题界面。

**状态标记**：`已完成` 已上线 · `部分` 有基础能力但缺关键环节 · 空白 未做。
工作量与优先级沿用原评估，未随版本调整。

## H. 工程遗留（实际运行暴露、不在 A–G 分类内）

这些问题来自线上部署与实测，不属于功能扩展，但都会影响可信度或数据安全。

| # | 问题 | 现状与影响 | 工作量 | 优先级 |
|---|---|---|---|---|
| H1 | **缺采空洞不可见** | 曲线 X 轴按数据首末点绘制，服务停机几天的空缺会被一条直线连起来，看不出断采 | 0.2d | ★★★ |
| H2 | **历史查询无索引** | 按日期分片裁剪，但单日区间仍需顺序解析当天约 8600 行；数据量上去后单日查询会变慢 | 1d | ★★ |
| H3 | **大区间点数约损失一半** | 磁盘降采样点与内存原始点时间戳不重合，去重失效后触发二次降采样（30 天请求 1200 实得约 606） | 0.2d | ★★ |
| H4 | **型号/SN 依赖「关于」页行 id** | 从 `/CH/about/about.shtml` 按行 id 解析，固件改 id 就读不到，目前无兜底与告警 | 0.5d | ★★ |
| H5 | **凭据明文落盘** | API 已脱敏，但 `data/devices.json` 中设备网页密码仍为明文，能读到文件即等于拿到设备 | 0.5d | ★★★ |
| H6 | **无异机备份** | 归档只有本机 `.jsonl.gz`，容量回收是**删除且不可逆**，磁盘故障即全部丢失 | 0.5d | ★★★ |

## 建议的推进顺序

**第一梯队（先把系统变得"敢用"）**
1. E1 开机自启/EXE —— 否则重启电脑就断
2. E2 配置与数据备份 + H6 异机备份 —— 回收不可逆，资产数据必须有副本
3. A4 批量导入导出 —— 12 台设备录入效率
4. G1 最小鉴权 + G5 凭据分级可见 + H5 凭据加密落盘 —— 内网也需要基本防护
5. B3 维护窗口静默 —— 避免检修时误报
6. H1 缺采空洞可见（0.2d，成本极低，直接提升曲线可信度）

**第二梯队（让它真正好用）**
6. A1 维保合同 + 到期提醒
7. C2 统计报表 + C4 电池健康度
8. B2 告警工单化 + D1 企微应用消息
9. G2 角色细分 + G4 审计日志

**第三梯队（规模化后再说）**
10. B1 巡检工单、C3 能耗分析、C5 预测性维护、A5 机柜定位、F3 大屏
