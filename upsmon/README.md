# UPS 监控台（Vertiv ITA2 · Web JSON 直采）

一套自建 UPS 监控系统：**直接轮询 UPS 内建 Web 的 JSON 接口**，跳过 SNMP。
新增一台 UPS 只需在后台录入 **IP + 网页账号 + 密码**，其余全部由设备自身返回。

> **回退版本**：同级目录 `../upsmon-v1-minimal/` 是只保留「采集 + 看板」的最小可用版，
> 完整版出问题时可直接切过去，详见该目录的 README。
>
> 仓库整体说明与**开发历程**见上级目录的 [`../README.md`](../README.md)。

## 二、为什么不用 SNMP，改用内建 Web JSON

在 Power Insight + VERTIV-ITA2-MIB 上实测下来的结论：

| 指标 | SNMP | 内建 Web JSON |
|---|---|---|
| 整机供电状态 | 枚举无映射，恒显示 `1`（other） | **逆变供电 / 旁路供电 / 联合供电**，设备自带中文定义 |
| 环境温度 | OID `.2.5.8` 返回 `65535`(0xFFFF)，显示 6553.5℃ | `envTemp` = 22.1℃（真实值） |
| 电池温度 / 湿度 | 无对应 OID | `HasTempSensor` / `HasHumiSensor` = 0（设备自述无传感器） |
| 固件版本 | 整棵 MIB 树里不存在 | Web 端也不提供 → 判定为**设备不支持** |
| 输入电流 | 缺失 | 有（3.20 A） |
| 线电压 / 三相 B、C | 缺失 | 有 |
| 累计电能 | 缺失 | 输入/输出各一个 MWh 计数器 |
| 视在功率、峰值因数 | 缺失 | 有 |

结论：**JSON 通道的数据完整度明显高于 SNMP**，而且枚举含义直接取自设备自身的前端
代码（`/_com/home/home.json` 的枚举定义与 `home.html` 中的中文注释一一对应），
不存在「模板映射写错」的问题。

## 三、看板的四种视图

顶栏一键切换，选择会持久化到 `data/settings.json`（`ui.viewMode`）。

| 视图 | 适用场景 | 特点 |
|---|---|---|
| **磁贴总览**（默认） | 30~40 台日常巡检 | 一格一台，8 列 × 5 行 = **40 台一屏看完**；每格显示供电状态大字 + 负载/输出/电池 + 负载进度条；离线/告警自动变色 |
| **设备卡片** | 少数几台、需要看趋势线 | 每台带输出电压/负载率双趋势线（带悬停读数）、完整指标网格、告警提示 |
| **列表** | 精确查数、批量核对 | 15 列表格，**点击表头排序**（名称/场地/状态/输出电压/负载/电池），可切「紧凑模式」提升一屏行数 70% |
| **分组** | 手动分组：面板固定展示**所有自定义组 + 未分组**，可折叠；把磁贴拖进自定义组即完成归组，拖回「未分组」即移出；组头显示台数、平均负载、告警数 |

三种视图都跟随顶部的「按型号/场地/状态/自定义分组」下拉，
并且都有 **「仅显示异常设备」** 开关——40 台时一眼定位问题设备。

### 拖动排序与拖动归组

* **磁贴和设备卡片都能直接拖动**（两者都支持，不是只有磁贴）
* 拖动时源半透明、目标位置显示蓝色插入指示线；**松手即存盘**，刷新页面后顺序保持
* 在「分组」视图里可以把磁贴**拖进另一个自定义分组**，或拖回「未分组」移出
* 动态分组（型号/场地/状态）由字段自动归类，不能靠拖动改变——那需要改设备的场地/型号字段
* 分组面板的展开状态会被记住，不会被 5 秒自动刷新折回去
* **拖动期间看板会暂停自动重绘**——否则 5 秒一次的重绘会把正在拖的元素从 DOM 移除，拖到一半就断
* **触摸设备**：长按约 0.26 秒激活拖动，出现跟随手指的幽灵元素
* **不想用拖拽也行**：列表视图和设备管理表每行都有 **↑ / ↓** 上下移按钮；
  列表视图第一列可切到「默认序」，直接看到拖拽/上下移的结果

### 性能
40 台实测：`GET /api/state` 返回 **50 KB / 96 ms**。
趋势序列由服务端随状态一起下发（每台 120 点），**前端不再逐台请求历史**，
否则 40 台时每 5 秒会产生 40 次额外请求 + 40 次磁盘读。

## 四、运行

```
双击 start.bat
```
浏览器打开 **http://localhost:8686**

* 端口：环境变量 `PORT` 可改（`set PORT=9000 && node server.js`）
* 数据目录：环境变量 `UPS_DATA_DIR` 可改（默认 `data/`，多实例并存时用）
* 依赖：**仅需 Node.js**（LTS 即可），**零 npm 依赖**
* 设备清单：`data/devices.json`（原子写入，可直接备份）

### 新增设备
点右上角 **「+ 添加 UPS」** → 选模板（可选）→ 填 **名称 / IP / 端口 / 网页账号 / 网页密码**，
再补 **所在场地 / 上线日期 / 服务商** 等台账字段 → 「测试连接」确认能读到数据 → 保存。
系统立刻开始采集，不用重启。

## 六、关键实现要点（踩过的坑）

### 1. 必须用 HTTP/1.0，不能用 keep-alive
ITA2 内建 Web 跑在 **lwIP 1.3.1** 上，只支持 HTTP/1.0。
Node 的 `fetch`（undici，HTTP/1.1 + keep-alive）和 PowerShell 的 `Invoke-WebRequest`
都会被对端直接 RST，表现为「登录成功但拿到的 SID 无效」「页面跳回登录页」。
`lib/http10.js` 手写请求行、固定 `Connection: close`、一请求一连接，实测 8/8 稳定。

### 2. 会话极稀缺，登录被限流
设备登录页内置提示 **「Too many users on-line. Please wait」**。
实测连续 5 次登录，只有 1 次真正建立可用会话，其余被拒。
所以：

* **登录一次，长期复用 SID**（实测同一 SID 连续轮询 8/8 成功，耗时 370 ms/次）
* 重新登录前先调 `/SignOut.cgi` 释放旧会话
* 驱动内建 **30 秒登录冷却**，失败按指数退避（最长 5 分钟）
* 采集失败时先判「会话丢失」再重登，不盲目重登

> 副作用一：人工打开 UPS 网页会挤掉监控会话，监控会在一个周期内自动恢复并重新建会话。
> 副作用二：**不要同时开两个监控实例连同一台 UPS**，它们会互相抢唯一的网页会话。

### 3. 传感器能力由设备自己声明
`/_com/status/battery.json` 里带 `HasTempSensor` / `HasHumiSensor` 标志位。
看板据此显示「设备不支持」，而不是把 `-100.0` 这类无效哨兵值当真实读数展示。

### 4. 单相机型的「线电压」是 0
设备对单相机型也返回 `L_L_Volt.A = 0`，采集侧直接置空，不展示「0.00 V」误导数据。

### 5. 明细接口做增量缓存
`input/output/load/battery` 四个明细接口每 3 个周期（≈30 s）拉一次，
但结果**增量保留**，所以在看板上任何时刻都能看到电能、视在功率等，不会因采集节奏而「缺项」。

### 6. 电压口径
JSON 里 `L_N_Volt` 是**相电压**（相对中性点，单相/三相都是 220V），
`L_L_Volt` 才是线电压（三相 380V）。所有阈值判定必须用相电压口径。

## 七、指标阈值（超限变色）

判定采用**相电压口径**。默认阈值：

| 指标 | 绿 → 黄 | 黄 → 红 | 依据 |
|---|---|---|---|
| 输出电压 | ±5% | ±10% | GB/T 7260 UPS 稳态 ±1%；GB 50174 末端 ±7%；GB/T 12325 |
| 输入电压 | ±10% | 超出 176~288V | ITA2 手册输入范围 176~288Vac（满载） |
| 旁路电压 | ±20% | 超出设备范围 | ITA2 手册旁路 -40%~+20% |
| 线电压(AB) | ±5% | ±10% | 三相标称 380V，单相不适用 |
| 输出电流 | 85% 额定 | 100% 额定 | 额定=容量÷220V(单相)或÷(√3×380V)(三相)；手册过载 105~125%/10min |
| 负载率 | 70% | 85% | UPS 长期负载率最佳区间 40%~70% |
| 电池容量 | 50% | 20% | 深放电显著加速电池老化 |
| 输出频率 | ±0.5Hz | ±2Hz | GB 50174 频率 50Hz±0.5Hz；设备范围 40~70Hz |
| 环境温度 | 30℃ | 35℃ | ITA2 工作 0~40℃ 不降额，50℃ 降额至 70%~80% |
| 三相不平衡 | 1% | 2% | GB/T 15543 电压不平衡度 ≤2% |

触发后**同时**影响：卡片左侧色条、状态徽章、对应数值颜色、对应趋势线颜色、
卡片底部提示语、设备严重级别（进而影响告警规则）。阈值可在「告警管理 → 指标阈值」
里直接改，也能一键恢复默认。

阈值判定结果也会作为告警规则的可用字段（如 `outputVoltageLevel = crit`）。

## 八、采集与存储策略

| 接口 | 频率 | 内容 |
|---|---|---|
| `/_com/home/home.json` | 每个周期（默认 10 s） | 概览：供电状态、三相电压电流频率、负载、电池、温度、告警计数、机型 |
| `/_com/status/{input,output,load,bypass,battery}.json` | 每 3 个周期（≈30 s） | 功率因数、累计电能、视在功率、峰值因数、传感器能力 |

* **历史永久保留**：`data/history/<设备ID>/<YYYY-MM-DD>.jsonl`，每行一个采样点（10 s 一条）
* 内存环形缓冲保留最近 3600 点（≈1 小时）用于看板快绘
* 查询历史时按需扫描对应日期分片，并按目标点数降采样（取桶内均值）
* 事件日志：`data/history/events.jsonl`，永久保留

## 九、已知限制

* **固件版本无法获取** —— SNMP 与 Web 两侧都不提供，已在详情页标注「设备不支持」。
* **电池温度 / 湿度需要选配传感器** —— 本机这几台未装（`HasTempSensor=0`），装了之后看板会自动显示。
* **没有身份认证** —— 当前内网开放访问。设计方案见 [`../docs/AUTH-DESIGN.md`](../docs/AUTH-DESIGN.md)，
  可按「最小可用版」半天工作量落地（管理员账号 + 登录页 + 写操作鉴权）。
* 采集端到设备之间是明文 HTTP，账号密码以明文存在 `data/devices.json`（API 返回已脱敏为 `********`），
  仅适合内网使用。
* 尚未做开机自启 / EXE 打包；目前需手工双击 `start.bat`。
