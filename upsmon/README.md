## 二、数据源选型：为何不使用 SNMP

在 Power Insight 与 `VERTIV-ITA2-MIB` 上的实测对比：

| 指标 | SNMP | 内建 Web JSON |
|---|---|---|
| 整机供电状态 | 枚举缺少映射，恒为 `1`（other） | 逆变供电 / 旁路供电 / 联合供电，枚举由设备提供 |
| 环境温度 | OID `.2.5.8` 返回 `65535`（0xFFFF），被解析为 6553.5 ℃ | `envTemp` 返回真实值（22.1 ℃） |
| 电池温度 / 湿度 | 无对应 OID | 由 `HasTempSensor` / `HasHumiSensor` 声明能力 |
| 固件版本 | MIB 树中不存在 | 由「关于」页面铭牌表提供 |
| 输入电流 | 缺失 | 提供（实测 3.20 A） |
| 线电压、三相 B/C 相 | 缺失 | 提供 |
| 累计电能 | 缺失 | 输入、输出各一个电能计数器 |
| 视在功率、峰值因数 | 缺失 | 提供 |

结论：Web JSON 通道的数据完整度明显更高，枚举语义直接取自设备前端实现
（`/_com/home/home.json` 的枚举定义与 `home.html` 中的注释一一对应），不存在模板映射错误的风险。

## 三、看板视图

顶栏切换，选择持久化于 `data/settings.json` 的 `ui.viewMode`。

| 视图 | 适用场景 | 特点 |
|---|---|---|
| 磁贴总览（默认） | 30~40 台日常巡检 | 8 列 × 5 行，单屏 40 台；每格显示供电状态、负载率、输出电压、电池容量与负载进度条；离线与告警自动变色 |
| 设备卡片 | 少量设备，需观察趋势 | 每台附带输出电压与负载率双趋势线（含悬停读数）、完整指标网格、告警提示 |
| 列表 | 精确查数、批量核对 | 15 列，表头排序（名称、场地、状态、输出电压、负载、电池），紧凑模式可提升单屏行数约 70% |
| 分组 | 按自定义分组查看 | 面板固定展示所有自定义组与未分组项，可折叠；组头显示台数、平均负载与告警数 |

三种卡片式视图均跟随顶部「按型号 / 场地 / 状态 / 自定义分组」下拉，并共享「仅显示异常设备」开关。

### 排序与归组

- 磁贴与设备卡片均支持拖动，源元素半透明，目标位置显示插入指示线，松手即持久化
- 分组视图内可将磁贴拖入自定义分组，或拖回未分组以移出
- 动态分组由设备字段自动归类，拖动不会改变归属
- 分组面板展开状态会被记住，不因自动刷新而重置
- 拖动期间暂停自动重绘，避免重绘移除正在拖动的节点
- 触摸设备长按约 0.26 秒激活拖动
- 列表视图与设备管理表提供上下移动按钮，作为拖动的替代操作

### 性能

40 台设备实测：`GET /api/state` 返回约 50 KB，耗时约 96 ms。趋势序列由服务端随状态一并下发（每台 120 点），前端不再逐台请求历史，避免 40 台规模下每 5 秒产生 40 次额外请求与磁盘读取。

## 四、运行

```
双击 start.bat
```

浏览器访问 **http://localhost:8686**。

| 项目 | 说明 |
|---|---|
| 端口 | 环境变量 `PORT`，默认 8686 |
| 数据目录 | 环境变量 `UPS_DATA_DIR`，默认 `data/`，多实例并存时用于隔离 |
| 依赖 | 仅需 Node.js，无 npm 依赖 |
| 设备清单 | `data/devices.json`，原子写入，可直接备份 |

### 新增设备

选择右上角「+ 添加 UPS」，可先套用模板，填写名称、IP、端口、网页账号与密码，再补充场地、上线日期、服务商等台账字段，点击「测试连接」确认后可保存。设备立即纳入采集，无需重启。

## 七、实现要点

### 1. 仅支持 HTTP/1.0

ITA2 内建 Web 运行于 **lwIP 1.3.1**，仅支持 HTTP/1.0。Node 的 `fetch`（undici，HTTP/1.1 与 keep-alive）与 PowerShell 的 `Invoke-WebRequest` 均会被对端 RST，表现为「登录成功但 SID 无效」或「页面跳回登录页」。`lib/http10.js` 手写请求行，固定 `Connection: close`，一请求一连接。

### 2. 会话数量受限且登录被限流

设备登录页内置「Too many users on-line. Please wait」限制，实测连续登录 5 次仅 1 次成功建立可用会话。处理策略：

- 登录一次后长期复用 SID（实测同一 SID 连续轮询 8/8 成功，约 370 ms/次）
- 重新登录前先调用 `/SignOut.cgi` 释放旧会话
- 驱动内置 30 秒登录冷却，失败按指数退避
- 采集失败先判定会话是否丢失，避免盲目重登

> 人工登录设备网页会挤占监控会话，系统会在下一采集周期自动重建；
> 同一台设备不应由两个监控实例同时采集，否则互相抢占会话。

### 3. 传感器能力由设备声明

`/_com/status/battery.json` 包含 `HasTempSensor` / `HasHumiSensor` 标志位。界面据此显示「设备不支持」，不将 `-100.0` 等哨兵值作为真实读数展示。

### 4. 单相机型的线电压为空

设备对单相机型返回 `L_L_Volt.A = 0`，采集侧将其置空，避免界面展示误导性的 0.00 V。

### 5. 明细接口增量缓存

`input`、`output`、`load`、`battery` 四个明细接口每 3 个周期（约 30 秒）拉取一次，结果增量保留，因此任意时刻均可展示电能、视在功率等字段，不因采集节奏出现缺项。

### 6. 电压口径

`L_N_Volt` 为相电压（相对中性点，单相与三相均为 220 V），`L_L_Volt` 为线电压（三相 380 V）。所有阈值判定采用相电压口径。

### 7. 历史查询按日期裁剪

分片文件名为 `YYYY-MM-DD`，定长零填充，字典序即时间序。查询时先计算区间对应的首末日，窗口外的文件不打开；区间内利用「分片按时间追加」的特性提前结束读取（保留 50 行容错以应对时钟回拨）。同一份 30 天数据（25.9 万行、74 MB）的实测结果：

| 查询 | 优化前 | 优化后 | 提升 |
|---|---|---|---|
| 最近 1 小时 | 404 ms | 10 ms | 39× |
| 最近 24 小时 | 371 ms | 20 ms | 18× |
| 最近 7 天 | 396 ms | 99 ms | 4× |

取点与统计合并为一次扫描；事件记录改为从文件尾部读取 512 KB，不再全量解析。

### 8. 归档与回收

归档将超期分片压缩为 `.jsonl.gz`，写入流程为：写临时文件、回读校验、与原文件逐字节比对、一致后删除原文件。回收按整天删除最旧数据，当日数据始终保留。两者均需在 `settings` 中启用，也可通过 API 手动触发。

## 八、指标阈值

判定采用相电压口径。默认阈值：

| 指标 | 正常 → 预警 | 预警 → 严重 | 依据 |
|---|---|---|---|
| 输出电压 | ±5% | ±10% | GB/T 7260 稳态 ±1%；GB 50174 末端 ±7%；GB/T 12325 |
| 输入电压 | ±10% | 超出 176~288 V | ITA2 手册输入范围 176~288 Vac（满载） |
| 旁路电压 | ±20% | 超出设备范围 | ITA2 手册旁路 -40%~+20% |
| 线电压（AB） | ±5% | ±10% | 三相标称 380 V，单相不适用 |
| 输出电流 | 额定 85% | 额定 100% | 额定 = 容量 ÷ 220 V（单相）或 ÷（√3 × 380 V）（三相）；手册过载 105%~125% / 10 min |
| 负载率 | 70% | 85% | UPS 长期运行最佳负载区间 40%~70% |
| 电池容量 | 50% | 20% | 深放电显著加速电池老化 |
| 输出频率 | ±0.5 Hz | ±2 Hz | GB 50174 频率 50 Hz±0.5 Hz；设备范围 40~70 Hz |
| 环境温度 | 30 ℃ | 35 ℃ | ITA2 工作 0~40 ℃ 不降额，50 ℃ 降额至 70%~80% |
| 三相不平衡度 | 1% | 2% | GB/T 15543 ≤2% |

阈值触发后同时影响卡片色条、状态徽章、数值颜色、趋势线颜色、卡片提示语与设备严重级别。判定结果同时作为告警规则的可用字段（如 `outputVoltageLevel = crit`）。阈值可在「告警管理 → 指标阈值」修改或恢复默认。

## 九、采集与存储策略

| 接口 | 频率 | 内容 |
|---|---|---|
| `/_com/home/home.json` | 每周期（默认 10 秒） | 供电状态、三相电压电流频率、负载、电池、温度、告警计数、机型 |
| `/_com/status/{input,output,load,bypass,battery}.json` | 每 3 周期（约 30 秒） | 功率因数、累计电能、视在功率、峰值因数、传感器能力 |

- 历史数据：`data/history/<设备ID>/<YYYY-MM-DD>.jsonl`，每行一个采样点，永久保留
- 内存缓冲：保留最近 3600 点用于看板快速绘制
- 事件日志：`data/history/events.jsonl`，永久保留
- 三相分相字段：`phases >= 3` 时额外记录 `vInA/B/C`、`vOutA/B/C`、`iOutA/B/C`
- 归档与回收策略见上文第七节第 8 条

## 十、已知限制

| 类别 | 限制 |
|---|---|
| 设备适配 | 型号、序列号、固件版本依赖「关于」页面铭牌表的行 id，固件修改行 id 时将无法读取 |
| 性能 | 历史查询未建立索引，单日区间仍需顺序解析当天分片 |
| 硬件能力 | 电池温度与湿度需选配传感器，未安装时显示「设备不支持」 |
| 安全 | 尚未启用身份认证，内网可匿名访问；采集链路为明文 HTTP，凭据以明文存于 `data/devices.json`（API 已脱敏） |
| 运维 | 尚未提供开机自启与 EXE 打包，需手工启动；无运行日志文件，输出仅至控制台 |
| 备份 | 归档与回收仅作用于本机磁盘，无异机备份，回收不可逆 |
